## Contenu livré (L25)

Ouvrir un projet **s'attache à sa session vivante** au lieu de démarrer une session vierge : le
cockpit détecte le transcript le plus récent du cwd et l'affiche **en direct** (on voit la
conversation en cours, ex. celle d'un terminal). Deux modes de conversation coexistent désormais :

- **F1 — Détection (Rust)** : commande `latest_transcript(cwd)` (`terminal.rs`) → le `*.jsonl` le
  plus récemment modifié du dossier de sessions du cwd, `None` sinon. Helper `transcript_dir`
  partagé avec `transcript_path` (échappement `escape_cwd` réutilisé, cross-OS, anti-traversal,
  aucune constante chemin en dur). Enregistrée dans `invoke_handler` ; miroir `backend.ts`.
- **F2 — Mode « attached » vs « owned »** : `Conversation.source`. À l'ouverture (clic/onglet/eager
  L24), `latestTranscript(cwd)` → `Some` = **attached** (tail du transcript **sans** `pty_runner_open`)
  ; `None`/hors-Tauri = **owned** (runner actuel). Le tailer démarre pour les deux sources ; le
  `PtyTerminal` n'est monté que pour `owned` (garde L10). `convertToOwned` (bouton) bascule un
  attaché en owned (spawn) pour interagir.
- **F3 — UI attachée** : badge **« session vivante · lecture seule »**, Chat en lecture seule +
  bouton **« démarrer un runner du cockpit »**, Shell attaché = bannière honnête (patron L11). Le
  « × » d'un onglet attaché **arrête le tailer** (pas de `pty.close`). Chip runner / bouton esc
  restreints à `owned`.

## Gardes (AR)
- **AR-1** : à l'ouverture = s'attacher à la session vivante (plus récente), sinon spawn.
- **AR-2** : attaché = **lecture seule stricte** (aucun `pty.write` vers la session externe → zéro
  conflit deux-process). Pour interagir : « démarrer un runner » (nouvelle session owned) ou le terminal.
- **AR-3** : on attache à la **plus récente** sans seuil d'ancienneté (MVP).
